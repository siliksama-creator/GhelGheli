# ۲. 🔴 کرش کامل پنل مدیریت — مهم‌ترین کشف

سه صفحه (لیگ، مدیریت چت، پشتیبانی) این الگو را داشتند:

```js
const load = () => request(...).then(...)   // بدون آکولاد
useEffect(load, [request]);
```

وقتی `load` یک **Promise** برمی‌گرداند، ری‌اکت آن را «تابع پاک‌سازی»
فرض می‌کند و هنگام خروج از صفحه صدایش می‌زند. Promise تابع نیست:

```
TypeError: n is not a function
```

**و کل پنل سفید می‌شد** — نه فقط آن صفحه.

## چطور پیدا شد

با پیمایش پشت‌سرهمِ همهٔ صفحه‌ها در مرورگر واقعی:

```
ورود → کارت و کد → جوایز → کیف پول → لیگ ماهانه → کاربران
⇒ بدنهٔ صفحه: ۰ بایت، دو خطای کنسول
```

**چرا تست‌های معمولی نمی‌گرفتندش:** فقط هنگام **خروج** از آن سه صفحه رخ
می‌داد. باز کردن تکیِ هر صفحه سالم بود.

| ۲ خطای کنسول | **۰ خطا** |

# ۳. مصرف حافظه — بدون کم شدن امکانات

## آواتارها: ۹۳٪ سبک‌تر

| | قبل | بعد |
|---|---|---|
| فرمت | PNG ۳۸۴×۳۸۴ | WebP ۲۵۶×۲۵۶ |
| حجم کل | ۲٬۴۰۸ KB | **۱۷۴ KB** |
| دیکد هر کدام | ۰.۵۶ MB | **۰.۲۵ MB** |
| انتخابگر پروفایل (۱۰ تا) | ۵.۶ MB | **۲.۵ MB** |

آواتار حداکثر در ۹۲ پیکسل منطقی دیده می‌شود، پس ۲۵۶ حتی برای نمایشگر
۳x هم بیش از کافی است.

**نکتهٔ ظریف:** کلیدِ ذخیره‌شده در دیتابیس همچنان `.png` است (سرور آن را
در لیست سفید اعتبارسنجی می‌کند و عوض کردنش یعنی مهاجرت دیتابیس). پس
`avatarAsset` ترجمه می‌کند — وب از اول این نگاشت را داشت، فقط اپ جا
افتاده بود. **۸ تست** این را قفل می‌کند، چون اگر کسی ترجمه را بردارد
همهٔ آواتارها بی‌صدا ناپدید می‌شوند.

## دفتر رخدادها: ۹۱٪ سبک‌تر

| | قبل | بعد |
|---|---|---|
| حجم پاسخ | ۱۹۳٬۷۹۸ بایت | **۱۷٬۵۲۴ بایت** |
| ردیف | ۵۰۰ یکجا | ۵۰ + صفحه‌بندی |

`SELECT a.*` ستون JSONB `metadata` را هم می‌آورد که فهرست هرگز نشانش
نمی‌دهد. روی گوشی همهٔ آن باید پارس و به‌صورت آبجکت دارت در حافظه نگه
داشته می‌شد.

**امکانات کم نشد:** هر رخدادی که قبلاً دیده می‌شد هنوز دیده می‌شود، و
جزئیات کامل از endpoint جدید در دسترس است.

### یک اشتباه که خودم کردم و رفع شد
اول نام ستون‌ها را **حدس** زدم (`entity_type`, `before_data`) و
endpoint را ۵۰۰ کردم. با خواندن schema واقعی
(`target_type`, `target_id`, `metadata`) رفع شد. درسِ آشکار: schema را
باید خواند، نه حدس زد.
