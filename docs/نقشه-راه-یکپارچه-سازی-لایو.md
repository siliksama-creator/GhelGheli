# نقشه‌راه — یکپارچه‌سازی کامل: پنل زنده، متن‌های زنده، اپ بدون آپدیت

تاریخ: ۳ سپتامبر ۲۰۲۶ · روی پایهٔ کامیت `f2daf1d` · این فایل **سندِ مرجعِ کارِ جاری** است
(پیش از این فقط در گفت‌وگو بود و در هیچ جا ذخیره نشده بود — همین باعث شد یک جلسه
دربارهٔ «فازها» حدس زده شود.)

> **راهِ تیک‌زدن:** هر بندِ انجام‌شده با ✅ و کامیتِ مرجع علامت می‌خورد.
> علامت ⬜ یعنی انجام‌نشده. `deploy` هر فاز جدا و با rollback خودکار است.

## ۰) وعدهٔ نهایی

| وعده | معنی دقیق |
|---|---|
| هر متن و عددی که کاربر می‌بیند، از پنل قابل تغییر است | وب کاربر + اپ اندروید — همه از یک منبع |
| تغییر = لحظه‌ای، بدون نصب | ذخیره در پنل → در اجرای بعدی کلاینت دیده می‌شود |
| اپ فقط برای «شیء جدید» آپدیت می‌شود | بازی/صفحه/ساختار UI تازه. هیچ عدد/متن/قانونی دلیلی برای آپدیت نیست |
| دو پنل ادمین (وب و اندروید) یک‌رنگ‌اند | همان منو، همان صفحه‌ها، همان API، همان اعتبارسنجی |
| زبان ساده برای ادمین غیرفنی | منوی گروه‌بندی‌شده، توضیح یک‌خطی، پیش‌نمایش زنده، واپس‌گیری |
| ظاهر اپ کاربری دست نمی‌خورد | فقط «درِ داده‌ها» عوض می‌شود |
| پیامک/OTP لمس نمی‌شود | روی حالت تست می‌ماند |

## ۱) وضعیتِ امروز (لحظهٔ نوشتنِ نقشه‌راه)

سالم و زنده (دست‌نخورده): `app_settings` + کشِ همگامِ `opsConfig`، دروازهٔ `GET /api/config`،
پنل‌های ادمین (۲۲ بخش در هر کلاینت)، خواندنِ همان API توسط هر دو کلاینت.

مانده‌ها: دستهٔ الف (۱۰ عددِ ساختاری هاردکد)، دستهٔ ب (۵ متنِ کهنه با عددِ زنده)،
و ۸ خطای واقعی (بخش ۴).

## ۲) معماری هدف — «یک کتاب، سه خواننده»

```
app_settings (تنها منبع حقیقت) + live_copy + live_rules
   ├── پنل ادمین وب  ──┐
   ├── پنل ادمین اندروید ──► همان API (PATCH + preview + history + revert)
   └── GET /api/config ──► AppConfig (اندروید) / liveConfig (وب) ──► متن و عددِ هر صفحه
```

سه قاعدهٔ غیرقابل‌انحنا:
1. هیچ رقمِ «بازاری» در متن UI کلاینت نباشد — از config یا از قالبِ `live_copy`.
2. هیچ عددِ کاری در کدِ کلاینت نباشد مگر **فول‌بکِ ایمن** برابرِ مقدارِ فعلیِ محصول.
3. هر مقدارِ تازه: اول در API، بعد در کلاینت (کلاینتِ قدیمی کلیدِ ناشناخته را نادیده می‌گیرد).

مکانیزمِ «لحظه‌ای»: prime کردنِ کش هنگام ذخیره · fetch در هر اجرا + بازگشت به پیش‌زمینه ·
`configVersion` برای دیباگ · `live_content_history` (۲۰ نسخه) + دکمهٔ «واپس‌گیری».
