# وب: ریسپانسیو، سرعت، و یکپارچگی موبایل/دسکتاپ — TODO و سند وضعیت

> سندِ کار برای ایجنت‌های بعدی. قبل از دست‌زدن به چیدمان/بیلد/nginx وب این را
> بخوانید. این فهرست **وضعیت واقعی** را نشان می‌دهد: هر چیزی که در مخزن یا روی
> سرور زنده سنجیده و تأیید شد تیک خورده (`[x]`)؛ کارِ ناتمام `[ ]` و کارِ
> نیمه‌انجام `[~]` است. تاریخ‌گذاری‌ها به تقویم شمسی است.

دو پرتال وب داریم (هر دو Vite + React، روی nginx):
- **پنل وب ادمین** — `admin/`، دامنه `admin.ghelghelishop.ir` (تنها راه مدیریت؛
  پنل ادمین از اپ موبایل حذف شده، بنگرید به `ADMIN_PANEL_MOBILE_RETIREMENT.md`).
- **وب کاربر** — `userweb/`، دامنه‌های `user.ghelghelishop.ir` و
  `register.ghelghelishop.ir` (آینهٔ وبِ اپ موبایل).

قیدهای پابرجا:

> **وضعیت (۱۴۰۵/۰۹/۱۶):** تمام کارِ کد/زیرساختِ این فهرست انجام و روی سرور زنده
> تأیید شد (HTTP/2، کش مدل‌ها، Brotli، immutable، preconnect/preload، ریسپانسیو
> موبایلِ پنل ادمین شامل صف بررسی/هدف لمسی/دکمهٔ بستن کشو، و تست خودکار چیدمان).
> تنها بازمانده یک **بازبینی دستیِ روی نمای واقعیِ گوشی** است (C1/C4): باز کردن
> `admin.ghelghelishop.ir` روی مرورگر گوشی و انجامِ یک تأیید/ردِ آزمایشی و چکِ
> فرم‌های طولانی. D2 آگاهانه تغییر نمی‌کند (قید آینهٔ اندروید).

- **وب کاربر باید آینهٔ اندروید بماند.** هر اصلاحِ دسکتاپ فقط داخل
  `@media (min-width: …)` می‌نشیند؛ قواعد پایه (موبایل) دست نمی‌خورد. تست
  `userweb/tool/desktop-layout.mjs` همین را می‌بندد.
- بک‌اند، مسیرهای پول/Invoicle و 2FA ادمین دست‌نخورده.

## B. سرعت/تحویل روی سرور

- [x] **B1. (بالا) HTTP/2.** — **انجام شد (۱۴۰۵/۰۹/۱۶):** هر سه بلوک ۴۴۳ به
  `listen 443 ssl http2;` تغییر کرد (سبک قدیم، سازگار با nginx 1.24 سرور).
  تأیید زنده: هر سه دامنه حالا `HTTP/2 200` پاسخ می‌دهند. نتیجه: مالتی‌پلکسِ
  ده‌ها فایل JS/CSS/woff2 روی یک اتصال، بارگذاریِ اولِ سریع‌تر مخصوصاً روی
  موبایلِ با RTT بالا.
- [x] **B2. (بالا) کشِ بلندمدت فایل‌های بزرگ `/ml/`.** — **انجام شد:** سنجش
  نشان داد `sface.onnx` (۳۷MB)، `card_embed…onnx` (۱۷MB)، `ort-wasm….wasm`
  (۱۱MB) و `ort.min.js` از catch-all با `no-cache` رد می‌شدند و هر بار باز شدنِ
  صفحهٔ کارت revalidate/دانلود می‌کردند. بلوک `location ^~ /ml/` با
  `Cache-Control: public, max-age=2592000` (۳۰ روز) به هر دو سایت اضافه و تأیید
  زنده شد.
- [x] **B3. Brotli برای محتوای متنی.** — **انجام شد (۱۴۰۵/۰۹/۱۶):** روی
  Ubuntu 24.04 / nginx 1.24 پکیج رسمی `libnginx-mod-http-brotli-filter` نصب و
  در `/etc/nginx/conf.d/10-brotli.conf` با سطح ۵ فعال شد (کپیِ مخزن در
  `deploy/nginx-brotli.conf`). تأیید زنده: JS/CSS حالا `content-encoding: br`،
  مرورگر قدیمی که فقط gzip می‌فهمد همچنان gzip می‌گیرد، و مدل onnx فشرده نمی‌شود.
  (نکته: این نسخهٔ ماژول دستور `brotli_vary` ندارد.)
- [x] **B4. (متوسط) پیش‌اتصال (preconnect).** — **انجام شد:** کاربرِ وب از قبل
  `preconnect` به `api.ghelghelishop.ir` داشت؛ به پنل **ادمین** هم
  `preconnect` + `dns-prefetch` به همان دامنه اضافه شد (RTT اول روی موبایل کم
  می‌شود).
- [x] **B5. (پایین) preload فونتِ وزن اصلی.** — **انجام شد:** کاربرِ وب از قبل
  دو وزنِ روی‌صفحه را preload می‌کرد؛ به پنل ادمین هم preload دو وزن
  (Regular برای بدنه، Bold برای تیتر/دکمه) اضافه شد تا FOUT/reflow نگیرد.
  (۱۰۳ Early Hints هنوز فعال نیست — موکول به آینده.)
- [x] **B6. (پایین) `immutable` روی کش `/assets/`.** — **انجام شد:** فایل‌های
  hashدار حالا `Cache-Control: public, max-age=31536000, immutable` می‌دهند
  (تأیید زنده) تا مرورگر حتی revalidate شرطی هم نکند.

> نکتهٔ معماری برای B2: مدل‌های ML بین ادمین و کاربر **تکراری**اند (۶۵MB در هر
> دو `public/`). چون روی دو دامنهٔ مجزا سرو می‌شوند، کش مرورگر مشترک نیست. اگر
> روزی خواستید، می‌توان `/ml/` را فقط از یک دامنهٔ static مشترک سرو کرد تا یک
> بار دانلود شود — کارِ جداگانه، فوری نیست.

## C. ریسپانسیوِ ادمین روی موبایل (تجربهٔ لمسی مدیر)

پوسته و گریدها آماده‌اند؛ این‌ها ریزه‌کاری‌های تجربهٔ لمسی‌اند که باید روی نمای
واقعیِ گوشی (≈۳۹۰px) بازبینی شوند.

- [x] **C1. (بالا) صفِ بررسیِ کارت روی موبایل.** — **انجام شد:** در
  `@media(max-width:640px)` عکس‌های مقایسه (کاربر ← طرح پیشنهادی) به گرید دوستونهٔ
  بزرگ (ارتفاع تا ۲۰۰px) تبدیل شدند تا چشمی سنجیده شوند، و دکمه‌های تأیید/رد
  تمام‌عرض با هدف لمسیِ ۴۶px شدند؛ سوییچ «در انتظار/تأیید/رد» wrap می‌شود.
  (تأیید بصری روی نمای واقعی گوشی هنوز به‌عنوان بررسی دستی باقی است ولی چیدمان
  تضمین‌شده است.)
- [x] **C2. (بالا) هدف‌های لمسی (tap target ≥ ۴۴px).** — **انجام شد:** در
  `@media(max-width:640px)` پنل ادمین، `.btn-icon` حداقل ۴۴×۴۴ شد (دکمه‌های
  کوچکِ عملیات جدول ۴۰×۴۰). فقط داخل media query موبایل؛ دسکتاپ دست‌نخورده.
- [x] **C3. جدول‌های دیتا روی موبایل.** — **انجام شد (در حد پربازده):** هر دو
  نوع جدول (`.data-table` مشترک و سه جدول inline اقتصاد بازی/صندوق) در ظرف
  `overflow:auto/overflowX:auto` محصورند پس صفحه را نمی‌شکنند؛ در بلوک ۶۴۰px
  سلول‌ها بزرگ‌تر (پدینگ ۱۰/۱۲، فونت ۱۳px) و متن‌های کم‌رنگِ درون جدول خواناتر
  شدند. (تبدیل کاملِ جدول به حالت کارتی به‌عنوان بهبود آینده باز است — اسکرول
  افقیِ محصور، تجربهٔ قابل‌قبول و امن است.)
- [~] **C4. (متوسط) فرم‌های طولانی (اقتصاد بازی، جوایز، pass).** — **بخشی
  انجام شد:** `.tier-edit` که `min-width:300px` داشت و روی گوشی باریک (~۳۶۰px)
  سرریز می‌کرد، در موبایل `min-width:0; flex-wrap:wrap` شد. بازبینیِ کاملِ بقیهٔ
  فرم‌ها روی نمای واقعی گوشی باقی است.
- [x] **C5. (پایین) دکمهٔ بستن (X) داخلِ کشو.** — **انجام شد:** در سربرگِ
  سایدبار دکمهٔ `sidebar-close` اضافه شد که فقط زیر ۹۶۰px (حالت کشو) دیده می‌شود
  و روی دسکتاپ پنهان است؛ scrim و انتخابِ آیتم هم کار می‌کنند.
- [x] **C6. state بارگذاری/خالی.** — **انجام شد (از قبل موجود):** کامپوننت‌های
  مشترک `Skeleton` و `EmptyState` در `components/ui.jsx` ریسپانسیو‌اند و در ۱۳–۱۴
  صفحه استفاده می‌شوند؛ روی موبایل هم درست کار می‌کنند.

> معیار پذیرش این بخش: مدیر روی **مرورگر گوشی** بتواند بدون اسکرولِ افقیِ صفحه و
> بدون دکمه‌های ریز، کار روزانه (تأیید کارت، پاسخ پشتیبانی، دید آمار) را انجام
> دهد.
