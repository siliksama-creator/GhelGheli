## ۱۱ باگ پیدا و رفع شد

### 🔴 بحرانی — از دست رفتن پول کاربران

**باگ ۱: تساوی امتیاز، جایزه لیگ را می‌بلعید**

`closeActiveSeason()` با `DENSE_RANK()` رتبه می‌دهد که در تساوی عمداً رتبه یکسان می‌دهد — رفتار درست ورزشی. اما جدول `league_payouts` قید `UNIQUE (season, rank)` داشت و درج با `ON CONFLICT DO NOTHING` بود:

```
تساوی برای رتبه ۳:
  بازیکن الف → رتبه ۳ → درج شد ✅
  بازیکن ب  → رتبه ۳ → تداخل → بی‌صدا حذف ❌
```

نفر دوم **هیچ‌وقت جایزه‌اش را نمی‌گرفت و هیچ خطایی هم ثبت نمی‌شد**. با امتیازهای صحیح، تساوی اصلاً نادر نیست.

رفع: قید درست «یک پرداخت به ازای هر کاربر در هر فصل» است (مایگریشن ۰۱۴).

---

**باگ ۲: لیگ هرگز بسته نمی‌شد**

اسکریپت `closeLeague.js` وجود داشت اما **هیچ cron ای برای اجرایش نبود**. فصل جاری در ۱ مرداد تمام می‌شد و هیچ اتفاقی نمی‌افتاد — نه جایزه‌ای، نه فصل جدیدی.

رفع: cron شبانه نصب شد. **هر شب** اجرا می‌شود نه فقط اول ماه، چون خود اسکریپت فصل ناتمام را رد می‌کند؛ پس یک شب از دست رفته (ری‌استارت، قطعی) کل ماه را بی‌پرداخت نمی‌گذارد.

---

**باگ ۳: بستن زودهنگام یا دوباره لیگ**

هیچ محافظی نبود. یک اجرای اشتباه وسط ماه، **امتیاز ماهانه همه کاربران را صفر** می‌کرد و جوایز نیم‌فصل را پرداخت می‌کرد.

رفع: ردیف فصل با `FOR UPDATE` قفل می‌شود، فصل بسته دوباره پرداخت نمی‌گیرد، و فصل ناتمام بدون `--force` بسته نمی‌شود.

```
$ node scripts/closeLeague.js
[league] skipped: season still running   ← محافظ کار می‌کند
```

### 🟠 امنیتی

**باگ ۴: path traversal در آواتار**

`profileAvatarKey` هر رشته‌ای را می‌پذیرفت. تست زنده:

```
PATCH /api/profile {"profileAvatarKey":"../../etc/passwd"}  →  200 OK ✅ ذخیره شد
```

هر دو کلاینت این مقدار را مستقیم در مسیر فایل می‌گذارند (`assets/avatars/$key`). رفع: فقط ده آواتار مجاز پذیرفته می‌شود. حالا `400`.

**باگ ۵: URL عکس بدون اعتبارسنجی**

`profileImageUrl` هر رشته‌ای را می‌پذیرفت، از جمله `javascript:` و `data:` که در یک webview اجرا می‌شوند. رفع: فقط مسیر آپلود خودمان یا `https://`.

---

### 🟡 خطای سرور به‌جای خطای کاربر

**باگ ۶: هر ۲۶ مسیر `:id` شناسه را اعتبارسنجی نمی‌کرد**

یک UUID نامعتبر مستقیم به Postgres می‌رفت، خطای `22P02` می‌داد و به‌صورت **۵۰۰ Server Error** برمی‌گشت:

```
GET /api/support/tickets/abc/messages  →  500 ❌
```

یعنی به کاربر می‌گفتیم «ما خراب شدیم» در حالی که واقعیت «ورودی‌ات غلط است» بود. ضمناً هر درخواست بی‌معنی یک اتصال استخر دیتابیس را می‌سوزاند — اهرم ارزان DoS.

رفع: میان‌افزار `validateUuid` روی **هر ۲۶ مسیر**. تست رگرسیون تضمین می‌کند مسیر جدیدی بدون آن اضافه نشود.

**باگ ۷: مقادیر مرزی پروفایل**

```
{"age":-5}      →  500  (نقض CHECK)
{"age":99999}   →  500
{"age":"abc"}   →  500  (22P02)
nickname ۳۰۰۰ حرفی → 500  (22001)
```

همه حالا `400` با پیام فارسی، یا trim می‌شوند.

**باگ ۸: JSON نامعتبر و مسیر ناشناخته**

JSON خراب پیام خام انگلیسی پارسر را برمی‌گرداند، و `/api/typo` صفحه **HTML** به کلاینتی می‌داد که فقط JSON می‌فهمد → خطای `Unexpected token '<'` در اپ.

### 🟡 موتور بازی

**باگ ۹: بازیکن در صف بی‌پایان جفت‌یاب گم می‌شد**

بعد از اعلان اول (۱۵ ثانیه)، بازیکن **هیچ سیگنال دیگری نمی‌گرفت**. دو مشکل:

1. سوکت بی‌کار پشت NAT اپراتور موبایل بعد از چند دقیقه بسته می‌شود → بازیکن بی‌صدا از صف حذف می‌شد در حالی که صفحه‌اش هنوز «در جستجوی حریف» نشان می‌داد، **برای همیشه**
2. ورودی مرده در صف می‌ماند → بازیکن بعدی با یک **شبح** جفت می‌شد

رفع: ping هر ۲۵ ثانیه که هم اتصال را گرم نگه می‌دارد هم سوکت مرده را از صف پاک می‌کند.

### 🟡 اندروید

**باگ ۱۰: `setState` بعد از `await` بدون بررسی `mounted`**

چهار مورد: `main.dart`، داشبورد، پروفایل، انتخاب پیوست. اگر کاربر صفحه را حین درخواست ببندد، اپ خطا می‌دهد (در نسخه release صفحه قرمز).

**باگ ۱۱: نشت حافظه در دیالوگ‌های ادمین + خطای بی‌صدا**

شش `TextEditingController` در دیالوگ‌های ویرایش کارت، امتیاز دستی و تنظیم رمز **هرگز dispose نمی‌شدند** — با هر بار باز کردن دیالوگ، بافر متن و listener ها تا پایان عمر اپ باقی می‌ماندند.

بدتر: خطای ذخیره **بی‌صدا** بود. دیالوگ بسته می‌شد، چیزی تغییر نمی‌کرد، و ادمین باور می‌کرد کار انجام شده. در مورد «تنظیم رمز موقت» این یعنی پشتیبانی رمزی به کاربر می‌گفت که هرگز تنظیم نشده بود.

## سیستم‌های ناتمام (دست نزدم، طبق درخواست)

### ۱. پیامک — کاملاً پیاده‌سازی نشده

| | |
|---|---|
| فایل سرویس | `smsService.js` **اصلاً وجود ندارد** (فقط در کامنت به آن ارجاع شده) |
| وضعیت | کد OTP تولید و در دیتابیس ذخیره می‌شود، ولی **هرگز ارسال نمی‌شود** |
| `OTP_DEV_MODE` | روی سرور `false` است (درست — وگرنه کد در پاسخ API برمی‌گشت) |

**تأثیر عملی:**
- «فراموشی رمز» کار نمی‌کند — کاربر باید از پشتیبانی بخواهد رمز موقت تنظیم کند
- تأیید شماره موبایل انجام نمی‌شود
- اعلان پیامکی (برنده لیگ، تأیید جایزه) وجود ندارد

**برای فعال‌سازی لازم است:** انتخاب سرویس‌دهنده (کاوه‌نگار، ملی‌پیامک، فراز اس‌ام‌اس)، خرید پنل و خط، تعریف قالب پیام در پنل اپراتور، و افزودن کلید API به `.env`. کد سمت سرور حدود ۵۰ خط است.

### ۲. پرداخت جوایز لیگ — نیمه‌دستی

جدول `league_payouts` وضعیت `pending/approved/paid` دارد و ادمین می‌تواند دستی تغییرش دهد، اما **هیچ اتصالی به درگاه بانکی یا سیستم انتقال وجه نیست**. یعنی ادمین باید خودش پول را واریز کند و بعد در پنل «paid» بزند.

### ۳. اعلان‌های Firebase — نیمه‌فعال

`firebase_messaging` در اپ نصب و مقداردهی شده و توکن FCM ذخیره می‌شود، اما بررسی کردم که سمت سرور کد ارسال اعلان push وجود ندارد. اعلان‌ها فقط درون‌برنامه‌ای (جدول `notifications`) هستند.

### ۴. تأیید ایمیل / احراز هویت دو مرحله‌ای

وجود ندارد. برای یک اپ وفاداری در این مقیاس لازم نیست، ولی اگر روزی پرداخت واقعی اضافه شود باید بازنگری شود.
