# سیستم بکاپ روزانه به تلگرام — راهنمای کامل

> وضعیت: ✅ **فعال و تست‌شده روی سرور واقعی**
> ربات: `@backupGhelGhelibot` · مقصد: چت خصوصی شما · هر شب **۳:۳۵ بامداد**

---

## خلاصه یک‌خطی

هر شب یک فایل ~۷۳۰ کیلوبایتی در تلگرام برایت می‌آید که **کل سیستم** داخلش است. اگر VPS از بین برود، همان فایل را روی یک سرور خالی باز می‌کنی، یک دستور می‌زنی، و همه‌چیز برمی‌گردد.

---

## چقدر پهنای باند مصرف می‌کند؟

| | |
|---|---|
| حجم فعلی هر بکاپ | **۷۲۸ کیلوبایت** |
| مصرف ماهانه (۳۰ شب) | **~۲۲ مگابایت** |
| مصرف سالانه | **~۲۶۰ مگابایت** |

**عملاً صفر.** پهنای باند ماهانه یک VPS معمولی چند ترابایت است؛ این کمتر از یک‌صدهزارم آن است. حتی اگر پایگاه داده صد برابر شود، بکاپ به ~۲۰ مگابایت می‌رسد که باز هم ناچیز است.

### چرا این‌قدر کوچک است؟

چون چیزهایی که **دوباره ساخته می‌شوند** را نمی‌فرستیم:

| شامل می‌شود ✅ | شامل نمی‌شود ❌ | چرا |
|---|---|---|
| دیتابیس کامل | `node_modules/` (~۴۰۰MB) | `npm ci` دقیقاً از روی lockfile بازسازی می‌کند |
| تصاویر آپلودی | `dist/` و `build/` | اسکریپت دیپلوی می‌سازد |
| `.env` و همه کلیدها | کد برنامه | از گیت‌هاب کلون می‌شود |
| گواهی SSL | لاگ‌ها | برای اجرا لازم نیست |
| تنظیمات nginx | | |
| کلید deploy گیت‌هاب | | |
| زمان‌بندی cron | | |
| **اسکریپت بازیابی** | | |

نکته آخر مهم است: **اسکریپت بازیابی داخل خود آرشیو سفر می‌کند.** اسکریپتی که فقط روی سروری باشد که از دست داده‌ای، به درد نمی‌خورد.

---

## 🔴 اگر VPS از بین رفت — دقیقاً چه کار کنی

### گام ۱ — یک سرور جدید بگیر
اوبونتو **۲۴.۰۴** (همان نسخه فعلی). حداقل ۲ هسته و ۲ گیگ رم.

### گام ۲ — فایل بکاپ را از تلگرام روی سرور جدید ببر

**راه ساده (پیشنهادی):** در تلگرام روی فایل بکاپ راست‌کلیک → **Copy Download Link**، بعد روی سرور:

```bash
ssh root@IP-سرور-جدید
wget -O backup.tar.gz "لینکی-که-کپی-کردی"
```

**یا** فایل را روی کامپیوترت دانلود کن و آپلود کن:
```bash
scp ghelgheli_full_*.tar.gz root@IP-سرور-جدید:/root/
```

### گام ۳ — یک دستور

```bash
tar xzf ghelgheli_full_*.tar.gz
cd ghelgheli_full_*
bash restore.sh
```

بعد `y` بزن. تمام. اسکریپت خودش:

1. Node، PostgreSQL، nginx، PM2، certbot، fail2ban را نصب می‌کند
2. دیتابیس و کاربرش را با همان رمز قبلی می‌سازد
3. کد را از گیت‌هاب می‌گیرد و **روی همان کامیتی که بکاپ از آن گرفته شده قفل می‌کند** (تا ساختار دیتابیس و کد هرگز ناهماهنگ نشوند)
4. `.env`، کلیدهای Firebase و کلید deploy را برمی‌گرداند
5. وابستگی‌ها را نصب و پنل‌های وب را می‌سازد
6. دیتابیس و تصاویر را برمی‌گرداند
7. nginx و گواهی SSL را برمی‌گرداند
8. سرویس را بالا می‌آورد
9. **زمان‌بندی بکاپ را هم دوباره نصب می‌کند** تا سرور جدید از همان شب از خودش محافظت کند
10. فایروال را فعال می‌کند و در آخر سلامت API را چک می‌کند

زمان تقریبی: **۵ تا ۱۰ دقیقه** (بیشترش نصب وابستگی‌هاست).

### گام ۴ — تنها کار دستی: DNS

در پنل دامنه‌ات، رکورد `A` این چهار زیردامنه را به IP سرور جدید تغییر بده:

```
api.ghelghelishop.ir
admin.ghelghelishop.ir
user.ghelghelishop.ir
register.ghelghelishop.ir
```

اگر بعد از پخش‌شدن DNS (معمولاً ۱۰ دقیقه تا ۲ ساعت) گواهی SSL کار نکرد:

```bash
certbot --nginx -d api.ghelghelishop.ir -d admin.ghelghelishop.ir \
        -d user.ghelghelishop.ir -d register.ghelghelishop.ir
```

## اگر بکاپ خراب شود چه می‌شود؟

**در همان تلگرام به تو خبر می‌دهد.** پیام قرمز «❌ بکاپ قل‌قلی ناموفق بود» با علت دقیق خطا.

این را واقعاً تست کردم (با یک دیتابیس نامعتبر شبیه‌سازی کردم) و هشدار رسید. زنگ خطری که تست نشده باشد، زنگ خطر نیست.

همچنین اگر حجم بکاپ روزی از ۵۰ مگابایت (سقف تلگرام برای ربات‌ها) بگذرد، به‌جای شکست بی‌صدا، هشدار می‌دهد.

## نکات امنیتی

⚠️ **فایل بکاپ رمزگذاری نشده** (طبق انتخاب خودت). یعنی هر کس فایل را داشته باشد، رمز دیتابیس و `JWT_SECRET` را دارد.

پس:
- **چت بکاپ را به کسی نشان نده** و کسی را به آن اضافه نکن
- اگر گوشی‌ات گم شد، در تلگرام از همه دستگاه‌ها خارج شو
- اگر بعداً خواستی رمزگذاری اضافه کنم، بگو — کار چند دقیقه‌ای است

🔒 **توکن ربات را جای امنی نگه دار.** اگر لو رفت، در @BotFather دستور `/revoke` بزن و بعد `setup_telegram_backup.sh` را دوباره اجرا کن.
